    quantpylib.wrappers.qfex

    quantpylib.wrappers.qfex module is our official QFEX wrapper SDK implementing the REST and WebSocket endpoints. The library is fully asynchronous, with normalized gateway methods and support for Feed and OMS. The websocket managers handle reconnections and resubscriptions.

    Examples

    example_qfex.py groups usage into exchange_endpoints(), gateway_endpoints(), ws_endpoints() and feed_and_oms(). Select the function to run in main() and uncomment the endpoints you want to use.

    Connections and order responses

    account_id=None selects the primary account. init_client() loads contract specifications and starts a pool of authenticated trade sockets (pool=8 by default). Each request borrows a socket exclusively; market data and account subscriptions use separate persistent connections. Call cleanup() when finished.

    Order submissions and cancellations observe immediate errors for timeout=0.5 seconds by default. A True result means no matching error arrived during that interval; acceptance, fills and cancellation outcomes arrive on the order-response stream. Use orders_mirror() or OMS to maintain order state. Queries such as get_user_orders() wait for their response. The wrapper does not automatically retry trading commands.

    Use a unique client order ID for each new order. QFEX permits duplicates, but the order mirror assumes uniqueness. Native modify_order() is disabled; cancel and submit a new order with a fresh client ID instead.

    Market caches

    With cache_stream=True, initialization subscribes to market statistics and waits for the first snapshot. get_all_mids(), get_all_marks() and get_funding_info() then read the latest cached values. Funding rates represent the one-hour funding interval. Books use their own subscriptions through l2_book_mirror() or Feed.

    add_order(symbol, side, order_type, order_time_in_force, quantity, price=None, take_profit=None, stop_loss=None, reduce_only=None, client_order_id=None, timeout=0.5) async

    Send an order and return True if no matching error arrives in the window.

    timeout is an error-observation window in seconds, with a 1 ms minimum. True does not confirm acceptance; acknowledgements, fills and rejections arrive on the account order stream. Native errors raise RuntimeError. Identical requests cannot be distinguished by their error echoes; supply distinct client_order_id values when submitting otherwise identical orders.

    add_stop_order(symbol, side, order_type, order_time_in_force, quantity, price, timeout=0.5) async

    Submit a TAKE_PROFIT or STOP_LOSS using the add_order wire message.

    True means no matching error arrived within the window. QFEX requires order_time_in_force for this request but does not use it for stop orders.

    add_twap(symbol, side, total_quantity, num_orders, order_interval_secs, reduce_only, client_twap_id=None, start_time=None, worst_price=None, timeout=0.5) async

    Submit a TWAP; True means no matching error arrived within the window.

    start_time is Unix seconds; omission starts immediately. worst_price is the IOC limit price for each child order. Cancel through order_cancel using twap_id or client_twap_id.

    WebsocketPool

    Maintain a hot pool of authenticated trade sockets for exclusive borrowing.

    Client initialization starts the pool. Transport ping/pong detects dead connections; pool workers replace closed sockets without reading application messages. Connection and authentication failures propagate without retrying.

    acquire() async

    Borrow a raw socket exclusively for a request or command error window.

    Do not subscribe on pooled sockets. The request helper handles late command errors. Let incomplete exchanges and unidentifiable responses raise through this block so the socket is closed before another borrower can use it.

    close() async

    Close all sockets and reject both queued and future borrowers.

    start() async

    Connect and authenticate every pool socket before returning.
